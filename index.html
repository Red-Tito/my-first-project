How to use ARC
as the central results engine

ARC (Automated Results Controller) is the nerve centre of the election night broadcast. It sits between the raw electoral data feed and every on-air graphics system, normalising results, triggering templates, and keeping the whole production in sync — without requiring a graphics operator to manually fire every update.

Operator Guide — Election Night
1
Load the Election Project
T–4 h
Open ARC and select the election project file. Verify that all constituency IDs, party colour mappings, and seat thresholds are correctly configured. Import the current candidate list from the electoral commission CSV or API endpoint.
2
Connect the Data Feed
T–2 h
In ARC's Data Source panel, point the REST connector at the electoral commission live feed URL. Set the polling interval to 60 s pre-close and 15 s once polls close. Run a dry-fire test using last election's data to confirm all graphic templates populate correctly.
3
Assign Graphics Outputs
T–2 h
Map each ARC template type to its target output: seat-count full-screens → Viz Trio channel A; lower-third ticker → Viz Trio channel B; national map → Touchscreen Data Wall engine; social card export → file drop folder for the digital team. Test all mappings with the cue preview mode.
4
Arm Auto-Trigger Rules
T–30 min
Configure ARC's trigger logic: auto-fire a full-screen result graphic whenever a constituency declares, auto-update the running total bar on every data poll, and alert the director via tally light when a seat changes party. Set the "sensitivity" threshold to avoid false triggers from partial-count updates.
5
Go Live — Monitor & Override
Live night
Once polls close, ARC runs autonomously — updating lower-thirds and maps with each data poll. The ARC operator sits on a secondary screen monitoring the queue. For urgent editorial overrides (e.g. hold a result the channel isn't yet ready to call), use the Hold button to pause auto-fire on a specific constituency without disrupting the rest of the queue.
6
Final Seat — End-of-Night Package
Last result
When the final seat is called, trigger ARC's "End-of-Night" macro: this fires the full national summary full-screen, exports a hi-res static results image for social, and writes the final JSON results file to the archive NAS. Log off the live data feed and save the session file for the post-mortem.

04. Election Night Workflow

Four stages from preparation to live output

01
Pre-Production
T-72 h to T-4 h before polls close
  • Load constituency templates into Viz Trio
  • Configure data API polling for electoral commission
  • Set up and test virtual studio environment in Unreal
  • Commission remote LiveU units at counting centres
  • Prepare ATEM macros for common transitions
  • Rehearse touchscreen data wall with presenter
02
Build-Up Coverage
T-4 h to polls close
  • Go live with studio programme — pre-analysis
  • Confirm all remote camera signals active
  • Run Viz Mosart automation dress rehearsal
  • Activate OTT stream; verify CDN delivery
  • Social team begins short-form content output
  • Technical checks on audio IFB for field crews
03
Live Results Night
Polls close → final seat called
  • Data API triggers automatic graphic updates in Viz Trio
  • Director calls shots via ATEM with Mosart assist
  • Results maps updated on touchscreen data wall
  • Remote live shots cut in from counting centres
  • Breaking results lower-thirds pushed in real time
  • HyperDecks record all ISO feeds continuously
04
Post-Production Wrap
Final seat called → T+6 h
  • Final results package rendered and archived
  • Clip team exports highlights for social platforms
  • All ISO recordings transferred to NAS storage
  • Debrief: flag any data sync issues for next time
  • OTT stream kept live for VOD replay window
  • Equipment strike and kit return to stores
